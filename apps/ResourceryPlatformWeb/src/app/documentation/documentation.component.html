Smart Serve v1.0 Documentation

Speech-to-Text Module

User Guide and System Documentation

1. Introduction

1.1 Purpose of This Document

This document provides user guidance for navigating and using the Speech-to-Text module of the SmartServe platform. It explains how users access the application, create accounts, authenticate, manage transcription requests, view transcription results, edit transcription records, and perform administrative activities.

The guide is intended to support user onboarding, training, system adoption, and the consistent use of the Speech-to-Text functionality.

1.2 Overview of SmartServe

SmartServe is a business automation and workflow digitisation platform designed to improve institutional processes, information management, and service delivery.

The Speech-to-Text module enables users to submit audio recordings for transcription through an AI-powered speech recognition engine. The module integrates with the World Intellectual Property Organization (WIPO) Speech-to-Text AI engine to support the conversion of spoken content into searchable text.

The module is intended to support meeting documentation, conference proceedings, institutional recordkeeping, and related documentation workflows.

1.3 Scope of the Module

The Speech-to-Text module provides the following user-facing functions:

  • Access to the SmartServe landing page.
  • User registration and login.
  • Access to the transcription workspace.
  • Creation of new transcription requests.
  • Viewing the list of transcription records.
  • Viewing individual transcription results.
  • Editing transcription information or text, subject to permissions.
  • Deleting transcription records, subject to permissions.
  • Administrative management of users, access rights, and system operations, as configured.

1.4 Intended Audience

  • General users submitting audio for transcription.
  • Conference and meeting documentation officers.
  • Institutional staff responsible for preparing meeting records.
  • Supervisors and reviewers responsible for validating transcription outputs.
  • System administrators responsible for access control and application administration.

2. Accessing the SmartServe Platform

2.1 Landing Page

The landing page is the initial entry point to the SmartServe Speech-to-Text module. It introduces the platform and provides users with access to the authentication functions required to enter the application.

Key elements may include:

  • SmartServe branding and application identity.
  • An overview of the Speech-to-Text service.
  • A Login button for registered users.
  • A Registration or Create Account option, where self-registration is enabled.
  • General instructions or information about the transcription service.

How to use the landing page:

  1. Open the SmartServe application using the URL provided by the system administrator.
  2. Review the information displayed on the landing page.
  3. Click Login if you already have an account.
  4. Click Register or Create Account if account registration is available to you.
  5. Follow the relevant instructions to proceed.

Expected outcome: The user is directed to the appropriate authentication page.

3. User Registration

3.1 Overview

Registration allows new users to create an account where self-registration is enabled. In an institutionally managed environment, access may instead be restricted to accounts created or approved by an administrator.

3.2 Registration Procedure

  1. Open the SmartServe landing page.
  2. Click Register or Create Account.
  3. Enter the requested registration details, such as name, email address, and password, as displayed on the registration form.
  4. Complete any additional required fields.
  5. Review the information entered.
  6. Click Register, Create Account, or the equivalent submission button.
  7. Complete any email verification or account activation process if required.

3.3 Successful Registration

After successful registration, the application should display an appropriate confirmation or direct the user to the login page, depending on the configured registration workflow. The user can then sign in when the account has been activated and access has been granted.

3.4 Registration Issues

  • Confirm that all mandatory fields have been completed.
  • Verify that the email address is valid.
  • Ensure that the password satisfies the application's requirements.
  • Check whether the email address is already registered.
  • Contact the system administrator if registration is restricted or approval is required.
Screenshot placeholder: Registration form

4. User Login

4.1 Overview

Login provides authenticated access to the SmartServe Speech-to-Text workspace. Users must sign in using valid credentials and must have the necessary permissions to access the module.

4.2 Login Procedure

  1. Open the SmartServe application.
  2. Click Login.
  3. Enter your registered email address or username, as applicable.
  4. Enter your password.
  5. Click Sign In or Login.
  6. Wait for the authentication process to complete.

4.3 Successful Login

After successful authentication, the user is redirected to the application workspace or the default page configured for the account. The available menus and functions depend on the user's assigned permissions.

4.4 Login and Access Issues

  • Verify the username or email address.
  • Check the password and try again.
  • Use the password recovery function if available.
  • Confirm that the account is active.
  • Contact the administrator if the account is locked, disabled, or lacks the required access rights.

Users should not share their passwords with other individuals.

5. Transcription List Page

5.1 Overview

The Transcription List page is the primary workspace for managing transcription records. It allows users to review existing submissions and initiate new transcription requests. The records and actions visible to each user depend on the application's access-control rules.

5.2 Key Features

  • A list or table of transcription records.
  • A New Transcription button.
  • Transcription titles or record identifiers.
  • Submission dates and other record details.
  • Processing status, where available.
  • Actions for viewing, editing, or deleting records, subject to permissions.
  • Search, filtering, sorting, or pagination controls, where implemented.

5.3 Viewing the Transcription List

  1. Sign in to SmartServe.
  2. Open the Speech-to-Text module from the navigation menu.
  3. Select Transcriptions or the equivalent menu item.
  4. Review the records displayed.
  5. Use available search or filtering controls to locate a specific record.

5.4 Understanding Transcription Records

Each record represents a transcription request or its resulting transcription output. Where supported, a record may contain the following information:

  • Transcription title.
  • Audio source or file reference.
  • Date submitted.
  • Processing status.
  • Transcribed text.
  • User or owner information.
  • Available record actions.

5.5 Access and Visibility

Users should only be able to access records permitted by the application's authorization and data-access rules. The availability of individual records may depend on whether the user is the record owner, belongs to an authorized group, or has an administrative role.

6. Creating a New Transcription

6.1 Overview

The New Transcription function allows an authorized user to initiate a new transcription request by providing the required audio input and associated information.

6.2 Procedure for Creating a Transcription

  1. Navigate to the Transcription List page.
  2. Click New Transcription.
  3. Review the fields presented on the new transcription form.
  4. Enter the transcription title or other required details.
  5. Select or upload the audio file, if the form supports file uploads.
  6. Complete any additional required fields.
  7. Review the information provided.
  8. Click Submit, Transcribe, or the applicable action button.
  9. Wait for the request to be processed.

6.3 Audio Submission

Users should provide an audio recording that meets the file requirements specified by the application.

  • The recording is audible and sufficiently clear.
  • The file is in a supported audio format.
  • The file does not exceed the configured size or duration limit.
  • The recording is appropriate for institutional processing and storage.
  • The user has the necessary authorization to submit and process the recording.

The available audio formats, size limits, and duration restrictions should be confirmed against the deployed system configuration.

6.4 Transcription Processing

After submission, SmartServe sends the transcription request through the configured speech recognition integration. The integrated WIPO Speech-to-Text AI engine processes the audio and generates text from the spoken content.

Processing time may depend on recording duration, audio quality, service availability, and system workload. Where a processing status is displayed, users should check the record for the latest available result.

6.5 Successful Submission

Once the request has been accepted, the user should be able to locate the transcription in the Transcription List page. Depending on the implementation, the transcription may be available immediately or after processing has completed.

7. Viewing a Transcription

7.1 Overview

The View Transcription function allows users to open a transcription record and review its details and generated text.

7.2 Procedure

  1. Open the Transcription List page.
  2. Locate the transcription you want to review.
  3. Click View, the record title, or the relevant view icon.
  4. Review the transcription details displayed.
  5. Read through the generated text and check it against the original recording where necessary.
  6. Use any available navigation, download, or export options if provided by the application.

7.3 Information Displayed

The transcription details page may display:

  • Transcription title and reference.
  • Source audio information.
  • Submission or creation date.
  • Processing status.
  • Generated transcription text.
  • Other metadata captured by the system.

7.4 Reviewing Transcription Accuracy

AI-generated transcriptions should be reviewed before being used as official institutional records. Users should pay particular attention to:

  • Personal names and institutional titles.
  • Acronyms and technical terminology.
  • Dates, figures, and monetary amounts.
  • Speaker attribution, where supported.
  • Words or phrases that may have been misrecognized.
  • Diplomatic, legal, or policy terminology.

Where the recording is unclear, the generated text should be checked against the original audio before final approval or circulation.

8. Editing a Transcription

8.1 Overview

The Edit Transcription function allows authorized users to modify editable information associated with a transcription. If the application permits direct text editing, users may also correct transcription errors in the generated text. The available editing options depend on the user's permissions and the functions implemented in the deployed version.

8.2 Procedure

  1. Navigate to the Transcription List page.
  2. Locate the record to be edited.
  3. Click Edit or the applicable edit icon.
  4. Review the information displayed in the editing form.
  5. Modify the permitted fields.
  6. Correct any transcription errors if text editing is supported.
  7. Review the changes carefully.
  8. Click Save, Update, or the applicable confirmation button.
  9. Verify that the updated information is displayed correctly.

8.3 Editing Guidelines

  • Preserve the original meaning of the speaker's statements.
  • Correct spelling, punctuation, and obvious recognition errors.
  • Verify names, figures, and technical expressions against the recording.
  • Avoid introducing statements that were not made in the original recording.
  • Follow institutional review and approval procedures where applicable.

8.4 Saving Changes

The application should confirm whether the changes were saved successfully. If an error occurs, review the information entered and try again, or contact the administrator. Where audit logging is enabled, changes may be recorded for accountability and traceability.

9. Deleting a Transcription

9.1 Overview

The Delete Transcription function allows authorized users to remove a transcription record where deletion is permitted by the application's access-control rules and institutional policies. Deletion should be performed carefully because it may affect access to the transcription and associated information.

9.2 Procedure

  1. Open the Transcription List page.
  2. Locate the transcription record to be deleted.
  3. Click Delete or the relevant delete icon.
  4. Review the confirmation message, if displayed.
  5. Confirm the deletion only if you are certain that the record should be removed.
  6. Verify that the record is no longer displayed in the list, where applicable.

9.3 Important Considerations

  • Confirm that the correct transcription has been selected.
  • Check whether the record is required for official documentation or archiving.
  • Follow applicable retention and records-management policies.
  • Obtain any necessary approval before deletion.

Deletion may be permanent or subject to a configured recovery mechanism. Users should not assume that a deleted transcription can be restored.

Where deletion is restricted to administrators, users without the required permission should not see or be able to execute the delete action.

10. Administration Page

10.1 Overview

The Administration page provides authorized personnel with access to administrative functions for managing the SmartServe application. Access to this page should be restricted to designated administrators or other users who have been granted the necessary permissions.

10.2 Accessing the Administration Page

  1. Sign in using an authorized account.
  2. Locate the Administration menu in the application navigation.
  3. Click the menu to open the administrative workspace.
  4. Select the required administrative function.

If the Administration menu is not visible, the account may not have the required permission, or the menu may not be enabled in the current deployment.

10.3 Administrative Functions

Depending on the deployed configuration, the Administration area may provide access to:

User Management

  • View registered users.
  • Create or update user accounts.
  • Enable or disable accounts, where permitted.
  • Review account status.

Roles and Permissions

  • Assign users to appropriate roles.
  • Grant or revoke permissions.
  • Control access to the Speech-to-Text module and its functions.
  • Restrict administrative capabilities to designated personnel.

Transcription Access Management

  • Review transcription records where authorized.
  • Support users experiencing access issues.
  • Apply configured access policies.
  • Manage records only where the administrator has the necessary permissions.

System Monitoring and Support

  • Review available system status information.
  • Investigate reported processing or access issues.
  • Escalate integration or service problems to the technical support team.
  • Monitor relevant application logs where authorized.

The functions actually available will depend on the SmartServe deployment and the permissions assigned to the administrator.

10.4 Access Control

Administrative access should follow the principle of least privilege. Users should receive only the permissions necessary to perform their assigned responsibilities.

  • General users: May create and view authorized transcription records.
  • Editors: May update permitted transcription information.
  • Supervisors: May review records within their authorized scope.
  • Administrators: May manage users, roles, and permissions.
  • Deletion rights: May be restricted to designated roles.

These examples describe a recommended access model and should be aligned with the permissions configured in the deployed application.

10.5 Administrative Responsibilities

  • Ensure that user accounts are appropriately managed.
  • Grant permissions according to approved responsibilities.
  • Review access issues and user reports.
  • Protect institutional information.
  • Follow applicable data protection and records-retention policies.
  • Escalate system errors and integration failures through the designated support process.

11. Security and Good Practice

  1. Protect account credentials and never share passwords.
  2. Sign out when using shared or public computers.
  3. Upload only recordings that you are authorized to process.
  4. Verify transcription accuracy before using the output as an official record.
  5. Avoid unnecessary duplication or deletion of institutional records.
  6. Respect the confidentiality of meeting discussions and associated documentation.
  7. Report suspicious activity, unauthorized access, or persistent application errors.
  8. Follow institutional information-security and data-protection policies.

13. Support and Escalation

Users experiencing persistent issues should contact the designated SmartServe support team or institutional system administrator.

When reporting an issue, users should provide:

  • A description of the problem.
  • The page or function where the issue occurred.
  • The approximate date and time of the incident.
  • Any error message displayed.
  • The relevant transcription reference, where appropriate and safe to share.

Passwords and other confidential authentication information should never be included in support requests.

14. Conclusion

The SmartServe Speech-to-Text module supports the digitisation of audio-based documentation workflows by enabling users to submit recordings, generate transcribed text, and manage transcription records within the platform.

Correct use of the module, appropriate access control, careful review of generated text, and adherence to institutional information-management policies will help improve the reliability, accessibility, and consistency of digital meeting documentation.
